M343 · Section 2 · The size of the nth generation

Composing P.G.F.s

Section 2 of M343 works out the probability generating function of a sum whose number of terms is itself random. Each move in that derivation has a figure below that you can play.

Where the derivation ends up
\[\Pi_Z(s) = \Pi_N\bigl(\Pi_X(s)\bigr)\]

The p.g.f. of \(N\), evaluated at the p.g.f. of \(X\).

The set-up

A sum with a random number of terms

Picture \(N\) parents. Parent \(i\) has \(X_i\) children, and \(Z\) is the total number of children:

\[Z = X_1 + X_2 + \cdots + X_N\]

The \(X_i\) are independent, each distributed like \(X\), and independent of \(N\). The awkward part is that the number of terms is random. In a branching process this is exactly how one generation becomes the next: \(N\) is the size of generation \(n\) and \(Z\) is the size of generation \(n+1\).

The needle stops at a random point and the segment it lands in gives \(N\). Segment widths are the probabilities \(P(N = n)\). Each parent then has 0, 1 or 2 children, independently of the others.

Step 1 · Theorem of Total Probability

Split the problem by the value of \(N\)

\[P(Z = z) = \sum_{n=0}^{\infty} P(Z = z \mid N = n)\,P(N = n)\]

Finding \(P(Z = z)\) head-on is awkward because you don't know how many terms are in the sum. If you did know \(N\), the problem would be routine. The Theorem of Total Probability lets you assume you know it: work out the answer separately for \(N = 0, 1, 2, \ldots\), weight each answer by the probability of that case, and add.

This is allowed because \(N\) must take exactly one of those values. The cases never overlap and together they cover everything, which is why the text opens by noting that \(N\) takes some value in \(\{0, 1, \ldots\}\).

Track \(Z =\)

Each strip is one value of \(N\), and its width is \(P(N = n)\). Inside a strip the blocks show the distribution of \(Z\) given that value, stacked from \(z = 0\) at the bottom, so a block's area is \(P(Z = z \mid N = n)\,P(N = n)\). The amber blocks are every way of getting the value you're tracking.

P(A | B) × P(B) is one strip on its own. Add up every strip to get P(A).

It is the same sum you use to turn segment rates into an overall rate: each segment's rate times that segment's share, added up.

Step 2 · Equation (2.9)

Swap the order of the sums

\[\begin{aligned}\Pi_Z(s) &= \sum_{z=0}^{\infty}\sum_{n=0}^{\infty} P(Z = z \mid N = n)\,P(N = n)\,s^z \\ &= \sum_{n=0}^{\infty} P(N = n) \sum_{z=0}^{\infty} P(Z = z \mid N = n)\,s^z\end{aligned}\]

Each term of the double sum is one cell of the table below, multiplied by \(s^z\). A cell holds the chance that \(N = n\) and \(Z = z\) happen together. The first line adds down each column first; the second adds along each row first. The cells are the same either way, so the total is the same.

Along a row \(n\) is fixed, so every cell in that row contains the same factor \(P(N = n)\), and it can come outside the inner sum. That is all the text means by \(P(N = n)\) being independent of the value of \(Z\): it doesn't change as \(z\) changes. It does not say that \(N\) and \(Z\) are independent random variables. They are strongly dependent.

Each cell is \(P(N = n)\,P(Z = z \mid N = n)\). Row totals give back \(P(N = n)\); column totals give \(P(Z = z)\).

Same number all along the row, so it comes out as a factor.

Step 3 · Result (2.8)

Inside a row, the sum has a fixed number of terms

\[\sum_{z=0}^{\infty} P(Z = z \mid N = n)\,s^z = \bigl(\Pi_X(s)\bigr)^n\]

Once \(N = n\), \(Z\) is just \(X_1 + \cdots + X_n\), an ordinary sum of \(n\) independent copies of \(X\). Result (2.8) gives its p.g.f. as \(\Pi_X(s)\) multiplied by itself \(n\) times. This is where the assumption that the \(X_i\) are independent of \(N\) gets used: knowing \(N = n\) must not change how the \(X_i\) behave.

For \(n = 0\) there are no terms. Then \(Z = 0\) for certain, its p.g.f. is \(s^0 = 1\), and \(\bigl(\Pi_X(s)\bigr)^0 = 1\) as well. That is why the text checks \(n = 0\) separately.

\[\Pi_X(s) = 0.25 + 0.5s + 0.25s^2 = \tfrac14(1+s)^2\]

Step 4 · Equation (2.10)

Recognise the p.g.f. of \(N\)

\[\begin{aligned}\Pi_Z(s) &= \sum_{n=0}^{\infty} P(N = n)\,\bigl(\Pi_X(s)\bigr)^n \\ \Pi_N(s) &= \sum_{n=0}^{\infty} P(N = n)\,s^n\end{aligned}\]

Put Step 3 back into (2.9) and you get the first line, which is (2.10). Set it beside the definition of \(\Pi_N(s)\) on the second line. The coefficients are the same and the powers are the same. The only difference is the thing raised to each power, which is \(s\) in one and \(\Pi_X(s)\) in the other. So \(\Pi_Z(s)\) is \(\Pi_N\) evaluated at the point \(\Pi_X(s)\).

\(\Pi_Z(s)\)0.4309

Straight from the distribution of \(Z\) in Step 1: \(\sum_z P(Z = z)\,s^z =\) 0.4309

Read the composition as a pipeline: feed \(s\) into \(\Pi_X\), then feed the answer into \(\Pi_N\). Move the slider; the two routes always agree.

Same coefficients, same powers. Only the thing in the slot changes.

\[\Pi_Z = \Pi_N \circ \Pi_X\]
Check

Does the formula match real draws?

Expand \(\Pi_N\bigl(\Pi_X(s)\bigr)\) as a polynomial and its coefficients are the probabilities \(P(Z = z)\). Drawing thousands of families the slow way should land on the same numbers. The page opens with 1,000 families already drawn.

Grey bars: share of simulated families with each total. Petrol lines and labels: coefficients of \(\Pi_N\bigl(\Pi_X(s)\bigr)\).

The mean falls out too. Differentiate with the chain rule, put \(s = 1\), and use \(\Pi_X(1) = 1\):

\[\begin{aligned}E(Z) = \Pi_Z'(1) &= \Pi_N'\bigl(\Pi_X(1)\bigr)\,\Pi_X'(1) \\ &= E(N)\,E(X) = 1.7 \times 1 = 1.7\end{aligned}\]
Why it matters

Generation after generation

In a branching process, generation \(n+1\) is a random sum: each of the \(Z_n\) individuals in generation \(n\) has an independent number of offspring distributed like \(X\). Starting from one individual and applying the result once per generation gives:

\[\begin{aligned}\Pi_{Z_{n+1}}(s) &= \Pi_{Z_n}\bigl(\Pi_X(s)\bigr) \\ \Pi_{Z_n}(s) &= \Pi_X\bigl(\Pi_X(\cdots\Pi_X(s)\cdots)\bigr)\end{aligned}\]

The second line has \(\Pi_X\) composed with itself \(n\) times. Setting \(s = 0\) keeps only the constant term, so \(\Pi_{Z_n}(0) = P(Z_n = 0)\), the chance that the family has died out by generation \(n\).

Offspring mean
Generation

With mean 1 the expected size stays at 1 in every generation, yet the chance of having died out keeps climbing. The families that survive make up for it by being larger.

Galton posed the question of vanishing surnames in 1873, and Watson's reply in 1874 worked by iterating the generating function in just this way.

The same result applies wherever a random number of random amounts are added, such as claims per year and claim sizes in insurance, or fraud cases and loss per case. When the amounts aren't whole numbers, the same argument works with moment generating functions:

\[M_Z(t) = \Pi_N\bigl(M_X(t)\bigr)\]
